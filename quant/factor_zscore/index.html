量化交易 2026-07

标准化因子时用简单平均，我把市场风格看反了

一次真实的踩坑复盘：z-score 标准化里那个不起眼的均值口径，让我的市场基准偏离原点 2.1 个标准差，从此对市场大小盘风格的判断全错了。这篇文章讲清楚为什么风险模型里的均值必须市值加权。

一、先说结论：一个不报错的错误

做多因子风险模型，绕不开一个叫"标准化"的步骤。它本身简单到近乎无聊——把每个因子的暴露值减去均值、再除以标准差，转成"均值 0、标准差 1"的无量纲分。公式就是初中生都认得的 z-score：

Z-Score 标准化
$$z_i = \frac{x_i - \mu}{\sigma}$$
把不同量纲的因子（Size ≈ 22、Value ≈ 0.4、股息率 ≈ 0.01）拉到同一把尺子上，回归系数才能横向比较。

我在里面栽了个大跟头。这个 μ——减掉的那个中心点——我一开始用的是最自然的简单平均：把当天所有股票的暴露值加起来除以只数。看上去天经地义，代码也跑得顺顺当当，没有任何报错。

但正是这个选择，让我在衡量市场大小盘风格的时候，做出了一次彻底的误判。

教训先行：在横截面风险模型里，标准化的均值 μ 必须用市值加权均值，不能用简单平均。用错了程序不会报错，只会让你的"市场基准"悄悄偏离原点，进而把整个市场的涨跌错误地摊派到各个风格因子头上。

二、我到底看错了什么

先交代背景。风险模型（Barra 那一类）想回答的问题是：某一天，风格暴露高的股票和暴露低的股票，收益差了多少？比如"小盘股今天是不是跑赢了大盘股"、"高价值的票是不是比低价值的强"。这些风格因子的收益，被定义为相对市场基准的超额收益。

注意"相对市场基准"这几个字。这意味着有一个隐含的约定：市场基准本身，必须站在原点上——它在每个风格因子上的暴露都应该约等于 0。只有基准站在原点，"超额"这个词才有意义。否则你测出来的东西是被污染的。

当时我拿标准化后的因子跑回归，看到 Size 因子（市值因子）的收益是正的，于是下意识地判断"这段时间市场偏好大盘股"。结果拿真实的大小盘指数一对，风格其实是反过来的。我百思不得其解——数据没错、代码没错，结论怎么会反？

根子就在那个简单平均的 μ 上。

三、量化这个错误：Size 偏了 2.1 个标准差

问题的核心是：市场组合是市值加权的（大盘股权重高），但简单平均把每只股票同等对待。这两者一旦不一致，市场基准就不在原点了。

我拿 2022-06-30 这天的全市场 4663 只股票做了个实测，对比两种均值口径：

因子简单平均 μ市值加权 μσ两者差距
Size（对数市值）22.7025.151.152.1 σ
Value（1/pb）0.5140.6670.4690.33 σ
Dividend（股息率）0.01170.01780.02030.30 σ

这张表怎么读？如果我用简单平均去标准化 Size，那么市值加权的市场组合在 Size 上的残余暴露不是 0，而是 +2.12。

换句话说，"市场基准本身偏大盘"这个客观事实，会被我的错误标准化悄悄算进 Size 因子的收益里。我以为自己在测"小盘 vs 大盘的纯粹差异"，实际上掺进了"基准偏大盘"的系统性偏移。归因就这样失真了——市场整体的涨跌，被错误地记到了 Size 因子头上。

为什么偏偏 Size 最夸张（2.1σ），而 Value、Dividend 只有 0.3σ？因为市值和 Size 定义上强相关（市值大 → Size 大），加权和被加权的量是同一个东西，循环放大。Value 和 Dividend 差距小，但也非零，同样应该用加权。

四、为什么市值加权就对了：三层等价

这不是一个"经验法则"或者"业界惯例"，它有严格的数学理由。市值加权标准化，本质上等价于让风格因子与市场（国家）因子正交。我把它拆成三个逐层递进的命题。

命题一：市值加权 ⟺ 市场组合暴露恰为 0

市场组合在某因子上的暴露，就是各股暴露按市值加权的平均。把标准化后的 z 代进去：

市场组合的因子暴露
$$X_M \equiv \sum_i w_i z_i = \sum_i w_i\frac{x_i-\mu}{\sigma} = \frac{1}{\sigma}\Big(\sum_i w_i x_i - \mu\sum_i w_i\Big) = \frac{\sum_i w_i x_i - \mu}{\sigma}$$
其中 $w_i$ 是第 $i$ 只股票的市值权重，满足 $\sum_i w_i = 1$。

要让 X_M = 0，充要条件就是 μ = Σ wᵢxᵢ——也就是市值加权均值。反过来，如果用简单均值 x̄，那么 X_M = (Σ wᵢxᵢ − x̄) / σ ≠ 0。我前面 Size 实测到的那个 +2.12，就是这个 X_M。

命题二：组合暴露为 0 ⟹ 因子收益干净

横截面回归的形式是 rᵢ = f₀ + Σ fₖ·zᵢₖ + uᵢ，其中 f₀ 是国家/市场因子（代表市场整体涨跌）。两边按市值加权求和：

市场收益的分解
$$r_M=\sum_i w_i r_i = f_0\sum_i w_i + \sum_k f_k\Big(\sum_i w_i z_{ik}\Big) + \sum_i w_i u_i$$
若各因子都市值加权标准化，中间项 $\sum_i w_i z_{ik} = X_M = 0$，末项残差 ≈ 0，于是 $r_M = f_0$。

结果非常干净：市场收益 = 纯截距 f₀，风格因子一点都没泄漏进 r_M。市场整体的涨跌归 f₀，各风格的超额归 fₖ，两者井水不犯河水。

可如果用简单均值，X_M ≠ 0，那么 r_M = f₀ + Σ fₖ·X_M + …——市场的涨跌被错误地摊派到各个风格头上。我的 f_Size 就吸收了一部分"市场涨跌 × 2.12"。这就是为什么我看到的 Size 收益是假的：它里面混进了本该属于市场整体的部分。

命题三：本质是可识别性的正交条件

用加权最小二乘（WLS）的语言看，市值权重构成对角矩阵 W，定义加权内积 ⟨a,b⟩_W = Σ wᵢaᵢbᵢ。国家因子的暴露是全 1 向量 𝟙，风格因子的暴露是 zₖ。两者在 W 度量下正交的条件恰好是：

正交条件
$$\langle\mathbf{1},\mathbf{z}_k\rangle_W=\sum_i w_i z_{ik}=X_M^{(k)}=0$$
又回到了命题一。于是四件事完全等价 ⤵
四者等价
$$\mu=\textstyle\sum_i w_i x_i \iff X_M=0 \iff \mathbf{z}_k\perp_W\mathbf{1} \iff \text{风格与市场因子正交}$$

正交意味着回归矩阵 X'WX 中，国家因子与风格因子的交叉项为 0，矩阵块对角化，f₀ 和 fₖ 可以分离识别。不正交，两者部分共线，矩阵病态，系数"分不清账"——这正是我当初遇到的窘境。

收束一句：市值加权标准化，数学上等价于让风格因子与市场因子正交，从而市场收益归市场、风格超额归风格，互不串账。简单均值破坏这个正交性——它污染归因不是"不好看"，而是违反了可识别性的正交条件。

五、顺手记下的另外两个坑

既然聊到标准化，把同一步骤里另外两个同样"不报错"的坑一起记下。它们都藏在这个看似傻瓜的操作里。

坑一：横截面标准化，不是时序标准化

z-score 里的"均值和标准差在谁身上算"，有两种截然不同的做法：

横截面标准化（对）时序标准化（错）
μ/σ 算在同一天所有股票之间
PARTITION BY date		同一只股票的历史序列上
PARTITION BY instrument
回答的问题"今天这只票在全市场排多高""这只票今天比自己历史高还是低"
用没用未来数据否，只用当天截面是！σ 用到了未来的点，前视偏差
适合横截面风险模型时序策略（单标的择时）

风险模型比的是"同一天股票之间"，所以标准化也必须在当天截面内做。用时序标准化，等于拿"这只票和自己历史比"的分，去做"股票之间比"的回归——问错了问题，而且 σ 算到了未来的点，是赤裸裸的前视偏差。

坑二：多子项因子，先标准化再合成

像 Quality（ROE + CFOA）、EarningsYield（ETOP + CETOP）这类由多个子项合成的因子，合成顺序不能错：

ROE_raw  ──→ z-score ──┐
                        ├──→ (z_roe + z_cfoa) ──→ 再 z-score ──→ f_quality
CFOA_raw ──→ z-score ──┘

正确做法是各子项先各自 z-score，再等权相加，合成分再标准化一次（因为两个 z 相加后 σ 不再是 1）。错误做法是先把原始子项直接相加——ROE ≈ 0.014、CFOA ≈ −0.003 量纲不同，直接加等于让大尺度子项主导，加权失真。

六、正确的实现：一段可跑的 SQL

把上面的道理落到代码里。对去极值后的每个因子列，套同一个横截面标准化模板（w 为市值）：

std AS (   -- 横截面标准化：市值加权均值、简单 σ、PARTITION BY date
  SELECT date, instrument,
    (f_x - capw_mu) / NULLIF(sd, 0) AS z_x
  FROM (
    SELECT date, instrument, f_x,
      sum(f_x * w) OVER (PARTITION BY date) / sum(w) OVER (PARTITION BY date) AS capw_mu,
      stddev_samp(f_x) OVER (PARTITION BY date) AS sd
    FROM factor_wins            -- 上游：去极值后的因子 + 市值列 w
  )
)

三个要点对应前面三个道理：

  • PARTITION BY date 保证横截面，不跨期（对应坑一）；
  • μ 用 sum(f*w)/sum(w) 市值加权（对应本文主角，陷阱二）；
  • NULLIF(sd,0) 防某天该因子无波动时除零。

还有一条容易忽略的顺序铁律：缺失值填充 → 去极值 → 标准化。σ 必须在去极值之后算，否则极端飞点会污染 σ，把标准差撑大，其他正常值全被压扁。

验证：标准化后市场组合确实回到原点

拿同样的 Size、2022-06-30、4663 只股票做验证，市值加权标准化后：

指标数值含义
市值加权均值(z)0.0 ✓市场组合因子中性，基准回到原点（目的达成）
简单 σ(z)1.0 ✓量纲统一，可跨因子比较
简单均值(z)−2.12不是 bug，正是"大盘股 z 正、权重高；小盘股 z 负、数量多"导致简单平均偏负

最后那个 −2.12 和前面陷阱二里的 +2.12 互为镜像，自洽得让人安心：市值加权口径把基准拉回了原点，而简单平均口径下基准偏了整整 2 个标准差——这正是我当初看错市场风格的全部原因。

七、写在最后

这次踩坑给我最大的启发，不是"记住均值要市值加权"这条规则本身，而是意识到：数据处理里最危险的错误，往往是那些不报错的错误。

缺失值、类型不匹配这些错误会当场崩给你看，反而安全。而标准化里的均值口径、横截面还是时序、合成先后——用错了程序照跑，数字照出，只是每一个数都悄悄偏了。你甚至会拿着这些偏了的数，信心满满地得出一个完全相反的结论，就像我把市场风格看反了那样。

做量化久了越发觉得，写对代码只是及格线。真正的功夫在于知道每一步操作背后到底在假设什么——标准化假设了"市场基准站在原点"，而这个假设，只有市值加权才守得住。
